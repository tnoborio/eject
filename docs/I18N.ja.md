# 国際化

[English](I18N.md)

EJECTは最初から国際的なサービスとして設計します。人がボタンを押し、別の場所に
いる人のトレイが動くという中心体験は、ほとんど説明せずに言語の境界を越えられます。

## 初期言語

- `en`: プロダクト文言とリポジトリ文書の正本。
- `ja`: 最初の完全な翻訳。

英語を正本にするのは保守上の判断であり、すべての利用者に英語を初期表示するという
意味ではありません。最初はブラウザまたはOSの言語を使い、その後は利用者が明示的に
選んだ言語を保存します。

## プロダクト名

`EJECT`と⏏記号は言語によって変えません。周囲の説明、操作、通知、エラー、日時、
アクセシビリティラベルを翻訳します。

言語を表すために国旗を使いません。

## 通信ルール

サーバーは英語・日本語の完成文ではなく、意味を表すコードと構造化された変数を返します。

```json
{
  "event": "PERSON_EJECTED_YOU",
  "variables": {
    "actorDisplayName": "Kaz"
  }
}
```

クライアントが受信者の言語で表示します。

```text
en: Kaz ejected you.
ja: Kazがあなたをejectしました。
```

## メッセージ形式

- ICU MessageFormat互換の仕組みを使用する。
- 初期文言で少なくても、複数形ルールに対応する。
- 日時、数値、相対時間を言語に応じて整形する。
- 翻訳済みの断片を連結して文を作らない。
- 変数に意味のある名前を付け、エスケープする。表示名からマークアップを注入しない。
- 翻訳者へ文脈、必要に応じた画面、各変数の説明を提供する。
- 長い文章や異なる文字幅の文字体系をテストする。

## メッセージキーの例

```text
action.eject
action.ejectBack
event.personEjectedYou
event.trayOpened
event.commandDelivered
status.available
status.paused
status.offline
status.cooldown
error.driveBusy
error.driveUnsupported
error.resultUnknown
permission.allowPerson
permission.revokePerson
```

キーは英語表現ではなく意味を記述します。`kazEjectedYouText`や`greenButtonLabel`のような
キーは作りません。

## レイアウトとアクセシビリティ

- ビットマップ画像に文字を埋め込まない。
- 英語のボタン幅を前提にせず、操作領域を伸縮可能にする。
- ⏏などの記号に翻訳済みのアクセシブルネームを付ける。
- キーボード操作と見えるフォーカスを維持する。
- 配信・失敗状態を色だけで表さない。
- 表示名をUnicodeで保持し、双方向テキストを安全に扱う。
- 初期対象でなくても、文字列の伸長と将来の右から左への言語を妨げない設計にする。

## 言語設定の所有者

Webでは人の設定、サインイン前のネイティブ通知ではローカルアプリの設定を使います。
サーバー上のアカウント設定と同期しても構いませんが、送信者が受信者の通知言語を
選ぶことはできません。

## 文書ポリシー

すべての正本文書に対応する`.ja.md`翻訳を用意します。意味を変える変更では、同じ変更
内で両方を更新します。各ファイルから対応文書へリンクします。

機械翻訳を下書きに利用できますが、プロダクト用語、セキュリティ上の意味、同意文言は
リリース前に人がレビューします。

## 言語を追加する条件

対応済みと表明する前に、次を行います。

1. 必須メッセージ、通知、初期設定、権限、エラー、プライバシー、安全警告を翻訳する。
2. 用語集とサービス固有の「eject」の扱いをレビューする。
3. キー不足、変数一致、フォーマットを検査する。
4. Webとデスクトップの表示を目視確認する。
5. 言語選択、フォールバック、日時、表示名、アクセシビリティをテストする。
6. 将来の更新を担当する保守者またはレビュー経路を決める。

部分翻訳は実験的であると明示し、同意・セキュリティ文言に承認済みフォールバックが
ある場合にのみ提供します。
