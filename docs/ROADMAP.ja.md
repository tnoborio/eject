# ロードマップ

[English](ROADMAP.md)

一般的なソーシャルプロダクトへ投資する前に、物理的な感覚を検証します。各段階に
終了条件を設けます。機能数が増えること自体を進捗とはみなしません。

## Stage 0 — ハードウェアの事実確認

ローカルのみで動作するWindows検証プログラムを作り、明示的に選んだ一台の光学
ドライブを検出・ejectします。

検証項目：

- 対応予定の複数Windowsバージョン。
- 内蔵・外付けのトレイ式ドライブ。
- 空のトレイとメディア挿入時。
- 使用中、非対応、切断済み、トレイレス端末。
- 標準ユーザー権限での実行。
- 成功を物理的な開放と呼べるか、命令受理までしか分からないか。

**終了条件:** 任意コマンド実行を必要とせず、実機上で再現できる狭いWindows能力契約を
文書化できること。

テスト用ハードウェアを一時的に用意できない場合、Stage 0の不確実性とすべての安全境界を
維持する限り、protocolと制御面domainの作業を並行して進められます。並行作業はStage 0の
終了条件を満たさず、物理成功の主張や、ハードウェア契約前の公開remote deliveryを許可
しません。

## Stage 1 — 二人用プロトタイプ

異なるネットワーク上の二つのアカウントと二台のWindowsアプリを接続します。

含めるもの：

- アカウントへのサインイン。
- 一人一台の登録端末と許可済みドライブ。
- 方向を持つ明示的な権限。
- 一つのeject操作。
- 結果報告。
- ネイティブ通知。
- クールダウン。
- 一時停止と取り消し。
- EJECTし返す。

**終了条件:** 二人が物理的な呼びかけと応答を確実に完了し、要求・配信・結果を区別
できること。

## Stage 2 — 日英対応の非公開アルファ

既知の少人数を招待します。

追加するもの：

- 英語・日本語の完全な初期設定と通知。
- 招待と関係管理。
- おやすみ時間と受信者による制限。
- 署名済み配布と安全な更新経路。
- データ保存期間とアカウント削除。
- 運用上の無効化と緊急の全配信停止。
- 監視を伴わないプロダクト・セキュリティフィードバック収集。

**終了条件:** 参加者が同意モデルを理解し、アプリを運用可能で、不正利用制御が機能し、
最初のデモ後も物理現象が興味深さを保つこと。

## Stage 3 — 公開実験の判断

一般公開を前提にしません。次を評価します。

- 繰り返し利用の様子。
- 招待とインストールの摩擦。
- 対応ドライブの普及度。
- ハードウェア・サポート負担。
- 不正利用の試行。
- 希少性が意味を守れているか。
- EJECTを作品、ソーシャルトイ、継続プロダクトのどれとして扱うべきか。

**終了条件:** 継続、縮小、保存、拡張のいずれかを明示的に決定すること。

## macOS実験トラック

Stage 0でWindows上の物理契約を確立した後、macOSの実機検証を別に行います。定義した
ドライブ種別で目的の物理現象が起きない限り、論理的なディスクアンマウントをEJECT対応
とは呼びません。

## 保留中の問い

- Webとネイティブアプリの具体的な技術スタック。
- 認証プロバイダー。
- リアルタイム通信方式。
- コード署名・配布ベンダー。
- 回数・クールダウンの値。
- 関係を相互承認必須にするか。
- 一人が複数端末を登録できるか。
- 一般公開と収益化。
- 光学ドライブ以外の物理操作。

これらは忘れたのではなく、意図的に保留しています。前段階の証拠をもとに解決し、
決定を記録します。
